# CQ OS（苍穹模式）完整需求基线 V0.2

## 一、项目定位

CQ OS（CangQiong Operating System，苍穹操作系统）目标：

基于 DSH Creator 模式，创造 DSH 第五种 Agent 运行模式。

不是普通 AI 助手，也不是单纯 Coding Agent。

目标：

让 AI 从单一任务执行者，升级为具备组织、规划、开发、维护能力的 AI
软件工程组织。

CQ OS 不替代 DSH，而是在 DSH Harness、Preset、Plugin 体系基础上扩展。

------------------------------------------------------------------------

# 二、核心原则

## 1. 不重复造轮子

所有能力遵循：

1.  优先直接复用成熟开源项目。
2.  已有基础能力则二次开发。
3.  多个开源项目组合解决。
4.  没有成熟方案才自主研发。

CQ OS 的创新重点：

-   AI组织能力
-   工程治理能力
-   Agent协作规范
-   项目生命周期管理

------------------------------------------------------------------------

## 2. 一切皆插件

能力全部插件化：

-   Agent能力
-   模型能力
-   工具能力
-   工作流能力
-   记忆能力
-   治理能力

------------------------------------------------------------------------

# 三、新项目启动规则

任何项目禁止：

需求确认后直接开发。

必须经过：

需求分析 → 开源调研 → 技术决策 → 设计 → 开发

------------------------------------------------------------------------

## 开源优先规则

需求分析完成后：

必须检查：

-   GitHub开源项目
-   行业成熟方案
-   官方生态项目
-   类似产品实现

判断：

-   是否可以直接使用。
-   是否可以二开。
-   是否需要组合多个项目。
-   是否必须自研。

必须记录：

-   调研项目。
-   选择原因。
-   放弃原因。
-   最终方案。

------------------------------------------------------------------------

# 五、CQ Memory 项目长期记忆系统

这是 CQ OS 核心能力。

目标：

保存项目智能资产，而不是简单聊天记录。

------------------------------------------------------------------------

## 保存内容

### 项目背景记忆

包括：

-   项目目标
-   用户需求
-   业务背景
-   技术限制

------------------------------------------------------------------------

### 架构决策记忆

保存：

-   技术选型
-   设计原因
-   放弃方案
-   长期影响

------------------------------------------------------------------------

### 开发过程记忆

保存：

-   已完成任务
-   当前任务
-   未完成事项
-   问题记录

------------------------------------------------------------------------

### Agent执行记忆

保存：

-   哪个Agent执行
-   修改内容
-   修改原因
-   执行结果

------------------------------------------------------------------------

### Bug经验库

保存：

-   历史Bug
-   原因
-   修复方案
-   防止再次出现的方法

------------------------------------------------------------------------

### 用户偏好记忆

保存：

-   开发习惯
-   技术偏好
-   项目规则要求

------------------------------------------------------------------------

## 记忆要求

必须：

-   可查询
-   可更新
-   可追踪

-   数据库重大修改

# 十、Agent权限管理

每个Agent必须明确：

-   可执行操作
-   可访问资源
-   可修改范围

Developer禁止：

-   修改治理规则
-   删除核心数据
-   修改生产环境

------------------------------------------------------------------------

# 十一、仓库治理

项目仓库必须保持干净。

禁止：

-   v1/v2/v3复制全部源码
-   临时备份目录
-   重复工程文件

版本管理统一使用：

-   Git Branch
-   Git Commit
-   Git Tag
-   Git Release

------------------------------------------------------------------------

# 十二、版本迭代管理

管理：

-   当前版本
-   版本目标
-   修改内容
-   影响范围
-   测试结果
-   发布记录

每次迭代生成：

-   CHANGELOG
-   更新说明
-   风险分析

------------------------------------------------------------------------

# 十三、需求变更管理

需求变化必须：

-   分析影响范围
-   更新任务
-   判断架构影响
-   调整计划

禁止直接堆叠代码。

# 二十二、最终目标

CQ OS不是：

-   AI聊天工具
-   AI代码补全工具
-   普通Coding Agent

目标：

成为 DSH 生态中的第五种 Agent 运行范式。

让 AI 从执行任务，升级为能够组织、开发、维护长期软件工程项目的智能组织。
