# V2.1 CQ Memory 开源调研与方案决策

## 结论

采用组合方案：`.cq/` Git-backed Markdown 继续作为权威源；索引层默认零 npm 依赖，生成可删除、可重建的 `.cq/index.json`；元数据过滤使用索引，全文检索复用 DSH 原生 grep/glob。只有明确需要 SQL/FTS5 时，才评估 `better-sqlite3` 或复用 DSH 已有 SQLite/FTS5 方案。

## 候选判定

| 方案 | 判定 | 原因 |
|---|---|---|
| Git-backed Markdown | 复用 | 与 Git、项目隔离、可审查和长期工程知识一致 |
| DSH storage/domain/query | 复用/组合 | 第一方存储、schema、变更和 session 查询能力可复用 |
| `index.json` | 最小自研派生层 | 只负责从 Markdown 生成索引，不取代权威源 |
| node:sqlite | 暂缓 | Node 22.5+ 可零依赖，但当前 FTS5 能力不足，全文需 regex |
| better-sqlite3 | 条件二开 | MIT、Windows 预编译、FTS5；仅在索引过滤和 grep 不足时引入 |
| LanceDB | 放弃 V2.1 首期 | 向量优先、需 embedding、原生依赖过重 |
| Mem0 | 放弃 | 对话/Agent memory 模态，Python/服务依赖，与工程 Markdown 权威源冲突 |
| Letta | 放弃 | 完整 Agent runtime，需服务/Postgres，超出 CQ Memory 范围 |
| Zep | 放弃 | 服务/图谱基础设施重，事件记忆模态与 `.cq/` 权威源不匹配 |

## V2.1 schema

记录头部统一包含：`id`、`type`、`status`、`agent`、`commit`、`version`、`updatedAt`、`title`、`tags`。V1 缺失字段标记 `legacy`，不猜状态、不删除、不覆盖。

类型：`project`、`decision`、`progress`、`execution-summary`、`bug`、`preference`、`tech-debt`、`version`。

索引字段：`id/type/status/agent/commit/version/title/tags/updatedAt/path/hash`。索引可删除并从 Markdown 重建，索引本身默认不入 Git。

## 验收

- V1 记录可读取；
- 按 type/status/agent/commit/version 过滤准确；
- 全文查询复用 DSH grep/glob；
- 索引删除后可幂等重建；
- 重复和缺 commit 只报告，不静默修复；
- 不写入原始聊天和完整 Agent 日志；
- 迁移失败不破坏原文件。
