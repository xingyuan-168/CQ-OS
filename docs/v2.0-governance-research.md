# V2.0 Governance 开源调研与 PoC 记录

## 状态

调研完成，进入方案决策前。当前结论：V2.0 不引入第三方策略引擎，先复用 DSH 原生控制点；第三方引擎保留为明确的二开备选，必须在后续 PoC 证明原生能力不足后才允许引入。

## 调研矩阵

| 方案 | 类型 | 可借鉴能力 | DSH 兼容性 | 当前结论 |
|---|---|---|---|---|
| DSH `tools.guard()` | 官方原生 | 单调、fail-closed、按 Agent scope 的工具执行拒绝 | 直接兼容当前 Host | 复用，作为工具级总拦截点 |
| DSH `tools/pre-execute` | 官方原生事件 | allow/deny/ask，支持异步审批和取消信号 | 直接兼容当前 Tool Runtime | 复用，作为需要审批的工具门禁 |
| DSH `fs/write-intent` / `fs/edit-intent` | 官方原生事件 | 文件写入/编辑前单槽决策 | 直接兼容 fs provider | 复用，作为路径级控制候选 |
| DSH `approval.request()` | 官方原生 | fail-closed 人工授权、允许一次、审计成对记录 | 直接兼容 session turn | 复用，不重复造审批系统 |
| DSH `sandboxPolicy` | 官方原生 | workspace 边界、按请求解析策略 | 直接兼容当前工具执行 | 复用，不重复造沙箱 |
| DSH `subagent/start` / `end` | 官方原生事件 | 子 Agent 生命周期和父级 scope 观察 | 直接兼容当前 in-process provider | 复用，做委派审计/状态机 |
| Open Policy Agent / Rego | 开源策略引擎 | 通用策略语言、决策分离、Wasm 嵌入 | 可通过 OPA Wasm/适配层接入 | 备选二开；V2.0 首期不引入运行时依赖 |
| Cedar | 开源授权语言 | 关系型授权、可解释决策、拒绝原因 | Node/Express 生态可参考 | 备选二开；需验证文件/阶段/Agent上下文映射 |
| Casbin | 开源授权库 | ACL/RBAC/ABAC、Node.js 适配 | Node.js 集成较直接 | 备选二开；需验证策略审计和 fail-closed 语义 |
| Cerbos | 开源授权服务 | 外部 PDP、审计、策略管理 | 服务化接入成本较高 | 暂放弃 V2.0 首期；不适合当前进程内低延迟控制 |

## 许可证与供应链初筛

- OPA、Cedar、Casbin、Cerbos 均为成熟开源授权/策略方向，但最终引入前仍需锁定具体仓库、版本、许可证、依赖树和安全公告。
- V2.0 当前不引入 npm/runtime 依赖，因此避免增加策略引擎供应链、Wasm 二进制和跨进程服务风险。
- 若后续 PoC 证明必须引入第三方，必须新增许可证审查、SBOM、锁版本、漏洞扫描和回滚方案。

## DSH 原生 API 事实

已通过 Inspect 核实：

- `tools.guard(guard)`：注册单调 guard，任意匹配 guard 可返回 reason 拒绝；Agent-scoped guard 只覆盖该 Agent；返回 disposer。
- `tools/pre-execute`：waterfall，签名为 `exec, next`，支持 allow/deny/ask；异步 gate 必须观察 `exec.signal`。
- `fs/write-intent`：waterfall，写入前单槽决策；签名为 `target, actor, next`。
- `fs/edit-intent`：waterfall，编辑前单槽决策；签名为 `target, actor, next`。
- `approval.request(req)`：缺少 answerer、取消或不可用时 fail closed；`allowed-once` 是唯一允许授权。
- `sandboxPolicy.resolve(request)`：按 session cwd、审批模式和部署默认值解析每次调用边界。
- `subagent/start` / `subagent/end`：按 delegating parent scope 观察子 Agent 生命周期。

## 最小 PoC 结论

V2.0 首个 PoC 应只验证 DSH 原生能力，不写持久插件：

1. 一个临时 Agent-scoped `tools.guard()` 拒绝角色调用调度和 runtime-mutate 工具；
2. 一个临时 `tools/pre-execute` gate 对 Developer 委派返回 ask/deny；
3. 一个临时 `fs/write-intent` / `fs/edit-intent` guard 拒绝 `preset/` 和 `.cq/policy/`；
4. 使用现有 `approval.request()` 验证一次性人工授权与取消/拒绝；
5. 使用 `subagent/start/end` 生成最小提炼委派审计摘要；
6. 所有 probe 结束后卸载，不形成持久依赖。

## PoC 实际结果

- `tools/pre-execute`：成功。临时目标 `cq_governance_poc_target` 在工具 body 前被拒绝，返回 `V2 PoC denial: temporary target is protected.`，证明当前动态 Package 可以注册 waterfall 拦截。
- `ctx.tools.guard()`：失败。虽然 Inspect 的 `tools` Service 契约列出 `guard(filter)`，但动态 Package 注入的 `ctx.tools` 当前没有该方法，运行时返回 `TypeError: ctx.tools.guard is not a function`。
- 结论：V2.0 首期可确认 `tools/pre-execute` 为当前可用的硬拒绝候选；`tools.guard()` 的正确 owner、版本差异或注入方式必须在正式实现前继续定位，不得直接假设可用。
- 临时 PoC 已停止并删除，不形成持久能力。

## 方案决策前的阻塞条件

在上述 PoC 完成并通过测试前，不得：

- 引入 OPA/Cedar/Casbin/Cerbos 依赖；
- 写持久 Governance Plugin；
- 宣称 V2.0 已具备路径级硬 RBAC；
- 将 persona 规则描述成底层强制策略。
