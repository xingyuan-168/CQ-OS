# ADR-0020 草案：优先复用 DSH 原生治理控制点

## 状态

Draft，等待 V2.0 原生能力 PoC。

## 背景

V1 通过 persona、Skill、toolFilter 和行为验收实现治理，但路径/阶段/授权控制仍有软约束。V2.0 需要硬拒绝关键违规操作。

## 候选方案

1. 直接复用 DSH 原生 `tools.guard()`、`tools/pre-execute`、`fs/write-intent`、`fs/edit-intent`、`approval.request()`、`sandboxPolicy` 和 subagent 生命周期事件。
2. 二开 OPA/Rego、Cedar、Casbin 或 Cerbos。
3. 自研完整策略引擎。

## 当前建议

先选择方案 1 完成最小 PoC。DSH 已经提供工具、文件、审批、沙箱和子 Agent 生命周期边界；当前引入第三方策略引擎会增加依赖、策略映射和供应链复杂度。只有 PoC 证明原生控制点不能满足策略表达、审计或跨工具一致性时，才评估方案 2。方案 3 仅在所有成熟方案均无法嵌入时保留。

## 初步 PoC 结果

`tools/pre-execute` 已验证可注册临时 waterfall 并在工具 body 前返回 deny。`ctx.tools.guard()` 按 Inspect 契约应存在，但当前动态 Package 注入实例没有该方法，需继续定位正确接口后才能纳入正式设计。

## 待 PoC 验证

- Agent-scoped guard 是否能覆盖 Core/角色边界；
- pre-execute ask/deny 是否能安全等待审批并处理取消；
- fs intent 是否能拿到可靠路径和 actor；
- 拒绝是否覆盖所有实际写入工具；
- subagent 生命周期是否足以建立可追踪委派状态；
- 策略损坏时是否能 fail closed。

## 回滚

Probe 只通过临时动态插件运行并卸载；正式实现必须在独立 Git 分支，失败时回滚 commit/tag，不改官方 shipped preset，不编辑部署产物。
