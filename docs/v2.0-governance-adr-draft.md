# ADR-0020：优先复用 DSH 原生治理控制点

## 状态

建议接受。V2.0 原生能力 PoC 已完成，结论：当前运行时首期只把 `tools/pre-execute` 作为可用的工具级硬拦截点；其余控制点在动态 Host 端当前表面下不可用为强制控制，保留为正式维护预设阶段的验证项。

## 背景

V1 通过 persona、Skill、toolFilter 和行为验收实现治理，但路径/阶段/授权控制仍有软约束。V2.0 需要硬拒绝关键违规操作。

## 决策

首期复用 DSH 原生 `tools/pre-execute` 作为工具派发前的硬拒绝；不引入 OPA/Cedar/Casbin/Cerbos，不自研完整策略引擎。原因：原生控制点已覆盖工具门禁；第三方引擎增加依赖、策略映射和供应链复杂度；只有 PoC 证明原生不足时才评估。方案 3 仅在所有成熟方案均无法嵌入时保留。

## 已验证事实（PoC 实测）

- `tools/pre-execute`：可注册 waterfall，在工具 body 前返回 deny；本会话实际调用目标工具返回 `{probed:true}` 并触发监听，确认可重入。
- `tools.guard()`：源码和 Inspect 有 `guard(guard)`，但动态 Package 通过 `ctx.get('tools')` 获取的实例没有该方法（`tools.guard unavailable through ctx.get`）；不能作为当前可用的强制控制点。
- `fs/write-intent`：单槽 `FsWriteIntent` 决策，返回 `undefined` 继续无条件写入；动态 listener 未覆盖动态工具写入，且该工具默认 cwd 为 `C:\Users\84700` 而非项目工作区。路径级强制控制在当前动态 probe 形式下不可宣称可用。
- `approval.request()`：契约确认缺 answerer/抛错返回 `unavailable`（fail-closed），`allowed-once` 是唯一授权。但动态 Host 无 `AbortController` 内置，无法在当前环境合成可信 `AbortSignal` 实测调用；行为以 Inspect 契约为准。

## 未决项

- Agent-scoped guard 是否可覆盖 Core/角色边界（当前 `guard()` 写入 global，读取按 agent chainLayers，存在不对称）。
- pre-execute ask 是否可安全等待审批并处理取消。
- fs intent 在正式 Agent-scoped fs provider 上是否返回可靠路径与 actor。
- 拒绝是否覆盖所有实际写入工具。
- subagent 生命周期是否足以建立可追踪委派状态。

## 回滚

本 ADR 阶段不引入持久 Governance Plugin，不改官方 shipped preset，不编辑部署产物。正式实现（含维护预设）必须在独立 Git 分支，失败时回滚 commit/tag。
