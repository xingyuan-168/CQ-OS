# ADR-0022 草案：优先复用 DSH 原生模型路由

## 状态

Draft，DSH 原生路由研究完成；LiteLLM 仅在跨 provider failover、预算或成本聚合需求经 PoC 证实后引入，不修改 DSH settings。

## 决策建议

首期复用 DSH 的 per-agent `provider/model`、`agent/request` waterfall、`request/header`、`request/context`、assistant provenance 和同 provider retry。这样不增加模型代理、外部服务或供应链依赖。

自托管 LiteLLM 保留为条件增强：当原生能力无法满足跨 provider failover、虚拟模型名、预算或统一成本观测时，才作为 OpenAI-compatible provider/baseURL 后端组合接入。虚拟模型映射、fallback、预算和成本观测由 LiteLLM 负责。

## 关键验收

必须对账 DSH requested provider/model、LiteLLM served provider/model/cost 和故障注入 fallback。不能只检查 `agent(...,{provider,model})` API 存在，不能只询问模型身份。

## 回滚

PoC 使用隔离本地网关，不修改 DSH 默认模型和 settings；失败时关闭网关即可，不影响 V1/V2 默认 provider。
