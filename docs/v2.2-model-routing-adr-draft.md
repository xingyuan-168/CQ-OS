# ADR-0022 草案：优先复用 DSH 原生模型路由

## 状态

首期 PoC 通过，建议接受为 V2.2 原生路由决策；LiteLLM 仅在跨 provider failover、预算或成本聚合需求经 PoC 证实后引入，不修改 DSH settings。

## 决策建议

首期复用 DSH 的 per-agent `provider/model`、`agent/request` waterfall、`request/header`、`request/context`、assistant provenance 和同 provider retry。这样不增加模型代理、外部服务或供应链依赖。

自托管 LiteLLM 保留为条件增强：当原生能力无法满足跨 provider failover、虚拟模型名、预算或统一成本观测时，才作为 OpenAI-compatible provider/baseURL 后端组合接入。虚拟模型映射、fallback、预算和成本观测由 LiteLLM 负责。

## 关键验收

直连 provider 时，使用 DSH `request/header` 或 requestConfig 记录 requested route，并以 assistant provenance/request context 记录 served route；同 provider retry 从 `llm/retry` 事件核验。网关场景再增加 LiteLLM served provider/model/cost 与故障注入 fallback 对账。`tools/cq-route-audit.mjs` 校验最小 `{ requested, served, gateway, fallback }` 记录格式及是否发生 route change。不能只检查 `agent(...,{provider,model})` API 存在，不能只询问模型身份。

## PoC 结果

已通过真实 Host 动态工具探测：`agentDefaultModel.currentSelection()` 返回 `zai-coding-cn / GLM-5.3`，`llm.listProviders()` 返回 4 个 provider，构造的直连 requested/served 对账记录通过 lossless JSON 返回。未发起模型请求，未修改 DSH settings。当前首期原生路由验收通过；跨 provider fallback、成本聚合和 LiteLLM 仍为条件增强。

## 回滚

PoC 使用隔离本地网关，不修改 DSH 默认模型和 settings；失败时关闭网关即可，不影响 V1/V2 默认 provider。
